# Editorial and publication policy

## Canonical publishing model

The website version is the canonical article. Medium and DEV are later distribution channels, not primary sources. Syndicated versions must use canonical links when the platform supports them and should link prominently to the definitive project page and repository.

This branch creates website pages and publication-ready source material only. It does not publish, deploy, push, merge, alter DNS, or change the live site.

## Evidence hierarchy

Use sources in this order:

1. Current canonical CV for Rami's role, education, and carefully reviewed performance figures.
2. Public first-party repository documentation, tests, source code, release metadata, and demo assets.
3. First-party institutional or platform listings, such as RHU news or Arduino Library Manager.
4. Existing portfolio content only when it does not contain a `[VERIFY]` marker or conflict with a stronger source.
5. Existing first-person articles only for technical facts that can also be verified elsewhere. Anecdotes are not portable evidence.

## Conflict policy

- Prefer the narrower claim.
- State the hardware and measurement context with every performance number.
- Do not combine numbers measured on different devices into one result.
- Do not turn a team outcome into an individual outcome.
- Do not use a current CV line to rewrite historical project dates unless the connection is explicit.
- When a conflict cannot be resolved, remove the claim from public copy and record it under editorial notes.

## Voice

Write as a working engineer reflecting on real constraints. Favor concrete nouns, verbs, choices, and limits. Keep the rhythm varied. Use first person where it clarifies a decision; avoid autobiography invented around a repository.

Avoid:

- motivational openings;
- “in today's rapidly evolving world” language;
- breathless claims about disruption;
- fake quotations or reconstructed dialogue;
- invented emotional turning points;
- padded conclusions that merely restate the introduction;
- SEO keyword repetition that makes the prose worse.

## Review states

`ready` means the public record is strong enough to index now.

`review` means the page is useful to build, but at least one ownership, role, metric, collaborator-credit, date, or disclosure question remains. It must be noindex and absent from public indexes.

`hold` means the subject is confidential, private, sensitive, or too ambiguous to render. It stays in the registry only.

## Images and media

Real project media is preferred because it proves the work. Copy only first-party assets from public repositories or the existing portfolio. Preserve aspect ratio, write specific alt text, and include a short source credit when the asset came from a separate repository.

Do not use stock imagery to represent a project. Do not generate an image that could be mistaken for a real prototype, result, test, partner, or deployment.
